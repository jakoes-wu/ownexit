# VPS 选购与系统安装手册

[English](vps.en.md) | **简体中文**

这一页手把手带你从零准备好服务器：选什么样的 VPS、怎么下单、怎么装（或重装）操作系统、防火墙要注意什么，最后把它交给 ownexit。

做完这一页，你手里应当有：

- 直连：**1 台** VPS；链式：**2 台** VPS（中转机 + 出口机）。
- 每台机器的**公网 IPv4**、**SSH 端口**（多数是 22）和 **root 密码**。
- 系统是 **Debian 12** 或 **Ubuntu 22.04 LTS**，CPU 架构最好是 **x86_64（amd64）**。

> 价格、套餐和控制台界面经常变，以服务商官网当前为准。

## 1. 先决定要几台

| 你的情况 | 选择 | 需要几台 |
| ---- | ---- | ---- |
| 在你所在的地方能直接连上这台 VPS | 直连 | 1 台 |
| VPS 的 IP 在你那里连不上或很不稳定，但你需要的正是这个 IP | 链式 | 2 台：出口机（提供最终 IP）+ 中转机（你能连上、且到出口机线路好） |

拿不准就先买 1 台做直连；以后需要时再加一台中转机，原来那台改当出口机。

## 2. 选购要点

| 项目 | 怎么选 | 原因 |
| ---- | ---- | ---- |
| 操作系统 | Debian 12 或 Ubuntu 22.04 LTS（64 位） | 直连只支持 Debian / Ubuntu；链式需要 systemd，这两个系统都满足，也是本项目实际测试过的 |
| CPU 架构 | x86_64（amd64） | 已在云服务器上实测；arm64 链式也可用（已在 Ubuntu 22.04 arm64 虚拟机上测试，尚未在云服务器上测试），两台必须同架构 |
| 配置 | 入门套餐即可（例如 1 核、1 GB 内存） | 代理本身占用很少，主要看线路和流量 |
| 公网 IP | 一个独享 IPv4 | 网站看到的就是它；与他人共享或 NAT 机器不适用 |
| 流量 | 看月流量额度和超额规则 | 日常使用每月几十到几百 GB 不等，按自己用量估 |
| 地区与线路 | 出口机按你需要的 IP 归属地选；中转机选离你近、到出口机线路好的 | 对大陆访问延迟敏感时，优先考虑标明面向大陆优化的线路 |
| 计费 | 先选月付 | IP 质量和线路要实际用过才知道，不满意可以及早换 |
| 登录方式 | 能用 root 密码 SSH 登录 | ownexit 第一次运行时用一次 root 密码配免密，之后全用密钥 |

## 4. 下单

两家都是在套餐页直接下单，步骤一样：

1. 从第 3 节的入口进入，**注册账号**。
2. **选套餐**：按第 3 节写的套餐名选，周期先选月付。
3. **选系统镜像**：Debian 12 x64 或 Ubuntu 22.04 x64。下单页没得选的话，开通后在控制台重装（第 6 节）。
4. **选登录方式**：如果让你在“SSH 密钥”和“密码”之间二选一，选**密码**。只能选密钥的话见第 8 节。
5. **支付**：支持的支付方式结账页会列出。
6. 开通后**记下三样东西**：公网 IPv4、SSH 端口、root 密码。它们一般在开通邮件或控制台的实例详情页里；SSH 端口以那里显示为准，不一定是 22。

## 5. 检查这台机器

**看 IP 质量**：浏览器打开 `https://ipinfo.io/<你的IP>`，看归属地、运营商和类型（hosting 还是 isp）；再用 Scamalytics 一类的工具看风险分。不满意就尽早处理（换 IP 或退换机），规则各家不同，以服务商说明为准。

**看你能不能连上**（在你自己的电脑上，最好先关掉本机代理的 TUN 模式）：

```sh
nc -vz <你的IP> 22        # 端口不是 22 就换成实际端口；显示 succeeded / open 即可连通
```

- 能连上：可以做直连，或者当中转机。
- 连不上，或时通时断：不适合直连，可以当链式的出口机，再找一台你能连上的机器当中转机。

**（可选）手工登录看一眼**：

```sh
ssh -p 22 root@<你的IP>   # 输入 root 密码；第一次连接问 yes/no 时输入 yes
cat /etc/os-release       # 确认是 Debian 12 或 Ubuntu 22.04
uname -m                  # x86_64 即 amd64，aarch64 即 arm64
exit
```

这一步不是必须的，ownexit 会自己检查系统；但手工登录一次可以先确认密码没抄错。

## 6. 装或重装操作系统

新买的机器如果已经是 Debian 12 / Ubuntu 22.04，直接跳到第 7 节。以下情况建议先重装：

- 下单时选错了系统，或者服务商默认装了别的系统；
- 机器以前装过别的代理、面板或防火墙规则（链式要求机器上除 ownexit 自己的规则外没有任何 nftables 表，装了 UFW 的话必须是 inactive）；
- 想从一个干净的系统开始。

> 重装会**清空整台机器的数据**。机器上已经部署了 ownexit 链式的话，先在你电脑上运行 `ownexit chain --id <名字> rollback` 再重装。

重装入口在控制台的实例管理页（通常叫“重装系统”或 Reinstall），选 Debian 12 或 Ubuntu 22.04 的模板；需要先停机的话面板会提示。重装一般不换 IP。

重装之后：

- **root 密码可能变了**，以面板显示或邮件为准。
- **服务器的 SSH 主机密钥变了**。直接重新运行 ownexit 命令即可：发现免密登录失效时，它会先清掉你电脑 `known_hosts` 里这台机器的旧记录，再用新密码重新配免密。如果你自己用 `ssh` 手工登录时看到 `REMOTE HOST IDENTIFICATION HAS CHANGED`，运行 `ssh-keygen -R <你的IP>`（端口不是 22 时再运行 `ssh-keygen -R "[<你的IP>]:<端口>"`）后重新登录。

## 7. 防火墙与安全组

“安全组”或“防火墙”指服务商控制台里的入站规则，在机器外生效；很多服务商默认不启用。启用了的话：

| 部署方式 | 需要放行的入站 TCP 端口 |
| ---- | ---- |
| 直连 | SSH 端口；sing-box 代理端口（20000～59999 之间随机或用 `--proxy-port` 指定，部署输出里会显示）；订阅端口（20000～59999 之间随机，部署输出里会显示） |
| 链式·中转机 | SSH 端口；中转端口（20000～59999 之间随机，部署时生成） |
| 链式·出口机 | SSH 端口（只需对你和中转机开放）；Reality 端口（20000～59999 之间随机），至少允许中转机访问 |

部署前还不知道随机端口，最省事的做法是：部署时先不启用安全组，或临时放行 20000～65535；部署完按输出里的端口收紧。

机器**系统内**的防火墙：

- 直连：UFW 已启用时，ownexit 会自动放行代理端口和订阅端口；没启用就不会去开启它。
- 链式：要求 UFW 为 inactive、除 ownexit 自己的表外没有 nftables 表、legacy iptables 没有活动规则。出口机“只允许中转机访问 Reality 端口”默认由 ownexit 在出口机上加一张自己的 nft 表来实现（见[链式手册](chain.md)）。

## 8. 服务商只给 SSH 密钥登录怎么办

有些服务商或镜像默认关闭 root 密码登录。ownexit 遇到这种情况会以 `reason=password-disabled` 退出。两种处理方法：

1. 在控制台里给 root 设置密码、开启密码登录（很多面板有“重置 root 密码”按钮），然后重跑；
2. 不开密码登录：先运行一次 ownexit，让它在你电脑上生成专用密钥（`~/.ssh/ownexit/id_ed25519_root_<IP>_<端口>`），再通过服务商的网页终端（VNC / Console）把对应 `.pub` 文件的内容追加到服务器的 `/root/.ssh/authorized_keys`，然后重跑。

## 9. 交给 ownexit

把记下的信息填进命令（下面的 IP 是示例）：

```sh
# 直连：1 台
ownexit direct up --host 203.0.113.7            # SSH 端口不是 22 时加 --port 2222

# 链式：中转机 + 出口机
ownexit chain init --relay 203.0.113.10 --exit 203.0.113.20   # 端口不是 22 时加 --relay-port / --exit-port
ownexit chain --id main deploy
```

第一次运行会分别问每台机器的 root 密码（输入时不显示），之后全程使用密钥。接下来的步骤见[直连手册](direct.md)和[链式手册](chain.md)。

## 10. 安全建议

- root 密码设得复杂一些，不要发给任何人，也不要写进会提交或分享的文件。
- 配好免密、确认 ownexit 能正常登录后，可以考虑在服务器上关闭密码登录；关之前保留服务商网页终端作为兜底。
- 请遵守你所在地的法律法规和服务商条款。
